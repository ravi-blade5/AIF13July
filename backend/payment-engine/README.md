## Scope

This module implements the first backend Payment Engine automation slice:

- PE-001 Payment Ingress
- Canonical payment instruction persistence
- `Idempotency-Key` enforcement
- 24-hour idempotency deduplication
- Expired idempotency cleanup so keys may be reused after the deduplication window
- Duplicate replay response handling
- Conflicting duplicate payload rejection
- RFC 7807-style errors using Spring `ProblemDetail`
- Correlation ID propagation
- PE-002 validation placeholder port
- PE-005 orchestration placeholder port
- PostgreSQL persistence and Flyway migration

## API

### Initiate Payment

```http
POST /v1/payments
Content-Type: application/json
Idempotency-Key: demo-key-0001
X-Correlation-Id: optional-correlation-id
```

Example body:

```json
{
  "sourceChannel": "MOBILE",
  "rail": "SCT_INSTANT",
  "debtorAccountRef": "ACC-123456",
  "creditorAccountRef": "BEN-998877",
  "creditorIban": "DE89370400440532013000",
  "creditorBic": "DEUTDEFF",
  "instructedAmount": {
    "amount": 42.50,
    "currency": "EUR"
  },
  "requestedExecutionDate": "2026-07-13",
  "remittanceInformation": "Invoice 12345"
}
```

## Local Run

Set required environment variables:

```bash
export SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/mfg_payments
export SPRING_DATASOURCE_USERNAME=mfg_app
export SPRING_DATASOURCE_PASSWORD=change-me-locally
```

Run:

```bash
mvn spring-boot:run
```

## Security Notes

- Do not hardcode secrets.
- Database passwords must be provided through environment variables or a secure secrets manager.
- Customer IAM, PSD2 TPP validation, fraud, sanctions, and full orchestration are not implemented in this slice.
